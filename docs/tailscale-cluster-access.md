# Remote Cluster Access via Tailscale

This document describes how to access the **cereal** Talos Kubernetes cluster remotely using [Tailscale](https://tailscale.com). Once configured, you can use `talosctl` and `kubectl` from any device on your tailnet without exposing ports to the internet.

## Overview

The `cereal` cluster currently runs on the local network (`10.30.1.0/24`) with these nodes:

| Node | Role | Local IP |
|------|------|----------|
| `cereal` | Control plane | `10.30.1.50` |
| `snap` | Worker | `10.30.1.51` |
| `crackle` | Worker | `10.30.1.52` |
| `pop` | Worker | `10.30.1.53` |

Cluster endpoint: `https://cereal.nature.leafbit.uk:6443`

Tailscale provides two complementary mechanisms for remote access:

- **API Server Proxy** (via the Tailscale Kubernetes Operator) — exposes the Kubernetes API (`kubectl`) over your tailnet with identity-aware authentication.
- **Talos System Extension** — runs Tailscale directly on each Talos node, placing every node on the tailnet for `talosctl` access and node-to-node mesh connectivity.

You can deploy either or both depending on your needs.

## Prerequisites

| Tool | Purpose | Install |
|------|---------|---------|
| `tailscale` | VPN client / CLI | [Download](https://tailscale.com/download) |
| `kubectl` | Kubernetes CLI | `brew install kubectl` or [docs](https://kubernetes.io/docs/tasks/tools/) |
| `talosctl` | Talos CLI | `brew install siderolabs/tap/talosctl` |
| `helm` | Kubernetes package manager | `brew install helm` |

All machines (workstation + cluster nodes) must be on the **same tailnet**.

---

## Approaches

| Approach | What it enables | Complexity | Requires node reboot |
|----------|----------------|------------|---------------------|
| **A. Kubernetes Operator** | `kubectl` from anywhere | Low — deploys as pods | No |
| **B. Talos System Extension** | `talosctl` + node mesh | Medium — re-image nodes | Yes |
| **Both together** | Full remote management | Both of the above | Yes (for B) |

- Use **Approach A** if you only need `kubectl` access remotely.
- Use **Approach B** if you also need `talosctl` access to individual nodes, or want node-to-node Tailscale mesh instead of KubeSpan.
- Use **Both** for full parity with local-network access.

## The `.env` File

Create `talos/.env` (this file is gitignored — verify before committing):

```bash
# === Tailscale ===
# Your tailnet name (shown in Tailscale admin console under DNS -> Tailnet name)
TAILNET_NAME=your-tailnet-name.ts.net

# Tailscale OAuth client for the Kubernetes Operator (Approach A only)
# Create at: https://login.tailscale.com/admin/settings/trust-credentials
TS_OAUTH_CLIENT_ID=k123456CNTRL
TS_OAUTH_CLIENT_SECRET=tskey-client-k123456CNTRL-abcdef

# Tailscale auth key for Talos system extension (Approach B only)
# Create at: https://login.tailscale.com/admin/settings/keys
# Recommended: reusable + ephemeral + tagged tag:k8s-nodes
TS_AUTHKEY=tskey-auth-your-authkey-here

# === Kubernetes Operator ===
# Proxy mode: "true" (auth mode with identity impersonation) or "noauth"
TS_API_SERVER_PROXY_MODE=true

# === Cluster ===
# Local endpoint (used when on the LAN)
CEREAL_ENDPOINT_LOCAL=https://10.30.1.50:6443

# Tailscale endpoint (used after Approach A is deployed)
# This will be https://tailscale-operator.<tailnet-name>:443
CEREAL_ENDPOINT_TAILSCALE=https://tailscale-operator.${TAILNET_NAME}:443

# === Kubeconfig ===
# Path to the kubeconfig generated by talosctl
KUBECONFIG_LOCAL=./talos/kubeconfig

# Path to the kubeconfig we'll generate for Tailscale access
KUBECONFIG_TAILSCALE=./talos/kubeconfig-tailscale
```

**Load the `.env` file:**

```bash
# Bash / zsh
set -a && source talos/.env && set +a

# Or with direnv (recommended)
# Add to talos/.envrc: source_env .env
cd talos/
```

## Approach A: Tailscale Kubernetes Operator (Recommended for kubectl)

This deploys the [Tailscale Kubernetes Operator](https://tailscale.com/docs/features/kubernetes-operator) into the cluster. It exposes the Kubernetes API server over your tailnet as a secure HTTPS endpoint, using your Tailscale identity for authentication.

### Step 1: Configure Tailscale ACL tags

In your [Tailscale ACL policy](https://login.tailscale.com/admin/acls), add:

```json
{
  "tagOwners": {
    "tag:k8s-operator": [],
    "tag:k8s": ["tag:k8s-operator"]
  },
  "grants": [
    {
      "src": ["group:k8s-admins"],
      "dst": ["tag:k8s-operator"],
      "ip": ["tcp:443"]
    }
  ]
}
```

Create an OAuth client at `Settings -> Trust Credentials` with:
- **Scopes**: `Devices Core` (write), `Auth Keys` (write), `Services` (write)
- **Tag**: `tag:k8s-operator`

Copy the Client ID and Client Secret into `talos/.env`.

### Step 2: Install the operator with Helm

```bash
# Load environment
set -a && source talos/.env && set +a

# Add the Tailscale Helm repository
helm repo add tailscale https://pkgs.tailscale.com/helmcharts
helm repo update

# Install the operator with API server proxy enabled in auth mode
helm upgrade \
  --install \
  tailscale-operator \
  tailscale/tailscale-operator \
  --namespace=tailscale \
  --create-namespace \
  --set-string oauth.clientId="${TS_OAUTH_CLIENT_ID}" \
  --set-string oauth.clientSecret="${TS_OAUTH_CLIENT_SECRET}" \
  --set-string apiServerProxyConfig.mode="${TS_API_SERVER_PROXY_MODE}" \
  --wait
```

### Step 3: Verify the operator joined the tailnet

Open the [Machines page](https://login.tailscale.com/admin/machines) in the Tailscale admin console. Look for a machine named `tailscale-operator` tagged with `tag:k8s-operator`.

```bash
# Or verify in Kubernetes
kubectl --kubeconfig="${KUBECONFIG_LOCAL}" get pods -n tailscale
```

### Step 4: Configure Kubernetes RBAC for tailnet identities

The API server proxy in **auth mode** impersonates requests using the sender's Tailscale identity. You must grant permissions via Kubernetes RBAC.

**Option 1: Grant by Tailscale user email**

```bash
# Give your Tailscale user cluster-admin (for initial setup)
kubectl --kubeconfig="${KUBECONFIG_LOCAL}" create clusterrolebinding tailnet-admin \
  --clusterrole=cluster-admin \
  --user="your-email@example.com"
```

**Option 2: Grant by Tailscale group (recommended for teams)**

In your Tailscale ACL, define a group and grant:

```json
{
  "groups": {
    "group:k8s-admins": ["your-email@example.com", "teammate@example.com"]
  },
  "grants": [
    {
      "src": ["group:k8s-admins"],
      "dst": ["tag:k8s-operator"],
      "app": {
        "tailscale.com/cap/kubernetes": [
          {
            "impersonate": {
              "groups": ["system:masters"]
            }
          }
        ]
      }
    }
  ]
}
```

Then bind the impersonated group:

```bash
kubectl --kubeconfig="${KUBECONFIG_LOCAL}" create clusterrolebinding tailnet-masters \
  --group="system:masters" \
  --clusterrole=cluster-admin
```

**Option 3: Grant by Tailscale device tag**

For tagged devices (e.g., CI runners):

```bash
kubectl --kubeconfig="${KUBECONFIG_LOCAL}" create clusterrolebinding tailnet-readers \
  --group="tag:k8s-readers" \
  --clusterrole=view
```

Add to your Tailscale ACL:

```json
{
  "grants": [
    {
      "src": ["tag:k8s-readers"],
      "dst": ["tag:k8s-operator"],
      "ip": ["tcp:443"]
    }
  ]
}
```

## Approach B: Talos System Extension (Recommended for talosctl)

This installs Tailscale as a [Talos System Extension](https://github.com/siderolabs/extensions/tree/main/network/tailscale), running Tailscale directly on each node. This enables:

- `talosctl` access to each node via its Tailscale IP / MagicDNS name
- Node-to-node Tailscale mesh VPN (alternative/complement to KubeSpan)
- Access to node-level services (e.g., `http://node-ip:port` over tailnet)

### Step 1: Generate a Tailscale auth key

1. Go to `Settings -> Keys` in the [Tailscale admin console](https://login.tailscale.com/admin/settings/keys)
2. Generate an auth key with these settings:
   - **Reusable**: Yes
   - **Ephemeral**: Yes (nodes auto-remove from tailnet when offline)
   - **Pre-approved**: Yes (if device approval is enabled)
   - **Tags**: `tag:k8s-nodes`
3. Copy the key into `talos/.env` as `TS_AUTHKEY`

### Step 2: Configure Tailscale ACL for tagged nodes

```json
{
  "tagOwners": {
    "tag:k8s-nodes": []
  },
  "grants": [
    {
      "src": ["group:k8s-admins"],
      "dst": ["tag:k8s-nodes"],
      "ip": ["tcp:50000", "tcp:6443"]
    }
  ]
}
```

Port `50000` is the Talos API port. Port `6443` is the Kubernetes API port (if accessing node directly).

### Step 3: Build a custom Talos image with the Tailscale extension

Use the [Talos Image Factory](https://factory.talos.dev/) to create a custom schematic:

1. Select your Talos version (e.g., `v1.13.2`)
2. Select your architecture (`amd64`)
3. Under **System Extensions**, select:
   - `siderolabs/tailscale`
4. Copy the generated schematic ID

Or via curl:

```bash
cat > /tmp/tailscale-schematic.yaml <<'EOF'
customization:
  systemExtensions:
    officialExtensions:
      - siderolabs/tailscale
EOF

curl -X POST --data-binary @/tmp/tailscale-schematic.yaml \
  https://factory.talos.dev/schematics
# Response: {"id":"SCHEMATIC_ID_HERE"}
```

### Step 4: Create a Tailscale patch file

Create `talos/patches/tailscale.yaml`:

```yaml
# Tailscale system extension configuration
# Applied to all nodes via generate-configs.sh

apiVersion: v1alpha1
kind: ExtensionServiceConfig
name: tailscale
environment:
  - TS_AUTHKEY=${TS_AUTHKEY}
  # Optional: set hostname based on Talos machine network hostname
  - TS_HOSTNAME={{ .MachineConfig.MachineNetwork.Hostname }}
  # Optional: accept MagicDNS
  - TS_ACCEPT_DNS=true
```

> **Note**: The `{{ .MachineConfig.MachineNetwork.Hostname }}` syntax is for Talos templating. Alternatively, hardcode or use the per-node patches.

### Step 5: Update Talos configs to use the custom image and patch

Edit `talos/controlplane.yaml` and `talos/worker.yaml`:

```yaml
machine:
  install:
    # Change from default installer to custom schematic
    image: factory.talos.dev/installer/SCHEMATIC_ID_HERE:v1.13.2
```

Edit `talos/generate-configs.sh` to merge the Tailscale patch with node configs. Add to the patch merging logic:

```bash
# In generate-configs.sh, after other patch merges:
if [[ -f "${SCRIPT_DIR}/patches/tailscale.yaml" ]]; then
  yq eval-all '. as $item ireduce ({}; . *+ $item)' \
    "${output_file}" \
    "${SCRIPT_DIR}/patches/tailscale.yaml" \
    > "${output_file}.tmp" \
    && mv "${output_file}.tmp" "${output_file}"
fi
```

> **Important**: The `TS_AUTHKEY` must be substituted before the patch is applied. Either:
> 1. Use `envsubst` in the generation script, or
> 2. Store the auth key in `secrets.yaml` and have `generate-configs.sh` inject it.

### Step 6: Apply the updated configs (requires node reboot)

```bash
# Regenerate configs with Tailscale extension
./talos/generate-configs.sh

# Apply to each node (one at a time, they will reboot)
./talos/bootstrap.sh apply controlplane
./talos/bootstrap.sh apply snap
./talos/bootstrap.sh apply crackle
./talos/bootstrap.sh apply pop
```

After reboot, nodes appear in the Tailscale admin console as:
- `cereal` (control plane)
- `snap`, `crackle`, `pop` (workers)

All tagged with `tag:k8s-nodes`.

### Step 7: Update talosconfig for Tailscale endpoints

Edit `talos/talosconfig.template` to add Tailscale endpoints:

```yaml
context: cereal
contexts:
    cereal:
        endpoints:
          - 10.30.1.50        # Local LAN IP
          - cereal.tailnet.ts.net  # Tailscale MagicDNS (after Approach B)
        ca: ${TALOS_MACHINE_CA_CRT}
        crt: ${TALOS_CLIENT_CRT}
        key: ${TALOS_CLIENT_KEY}
```

Regenerate and use:

```bash
./talos/generate-configs.sh
export TALOSCONFIG=./talos/talosconfig
talosctl version --nodes cereal.tailnet.ts.net
```

## Configuring kubectl for Tailscale Access

After deploying **Approach A** (Kubernetes Operator), configure `kubectl` to use the Tailscale API server proxy.

### Using `tailscale configure kubeconfig`

The easiest method — Tailscale's CLI writes a kubeconfig context for you:

```bash
# Load .env
set -a && source talos/.env && set +a

# Add the Tailscale context to your existing kubeconfig
tailscale configure kubeconfig tailscale-operator

# Or specify the full Tailscale URL
tailscale configure kubeconfig "https://tailscale-operator.${TAILNET_NAME}"
```

This creates/updates `~/.kube/config` with a context named after the tailnet hostname.

### Manual kubeconfig (for custom paths)

Create `talos/kubeconfig-tailscale`:

```bash
kubectl --kubeconfig="${KUBECONFIG_LOCAL}" config view --raw > "${KUBECONFIG_TAILSCALE}"

# Update the server to point at the Tailscale operator
kubectl --kubeconfig="${KUBECONFIG_TAILSCALE}" config set-cluster cereal \
  --server="https://tailscale-operator.${TAILNET_NAME}:443"

# Verify the context is correct
kubectl --kubeconfig="${KUBECONFIG_TAILSCALE}" config get-contexts
```

### Switching between local and Tailscale access

```bash
# --- Local access (when on LAN) ---
export KUBECONFIG="${KUBECONFIG_LOCAL}"
kubectl get nodes

# --- Tailscale access (from anywhere) ---
export KUBECONFIG="${KUBECONFIG_TAILSCALE}"
kubectl get nodes
```

Or use `kubectl` with `--kubeconfig` directly:

```bash
alias k-local='kubectl --kubeconfig="${KUBECONFIG_LOCAL}"'
alias k-tailscale='kubectl --kubeconfig="${KUBECONFIG_TAILSCALE}"'
```

## Daily Workflow

### 1. Connect your workstation to the tailnet

```bash
# macOS / Linux
sudo tailscale up

# Verify connection
tailscale status
```

### 2. Load environment variables

```bash
cd /path/to/Nature
set -a && source talos/.env && set +a
```

### 3. Access the cluster

```bash
# --- kubectl via Tailscale (works from anywhere) ---
export KUBECONFIG="${KUBECONFIG_TAILSCALE}"
kubectl get nodes

# --- talosctl via Tailscale (requires Approach B) ---
export TALOSCONFIG=./talos/talosconfig
talosctl version --nodes cereal.tailnet.ts.net
talosctl dmesg --nodes snap.tailnet.ts.net
```

### 4. Switch back to local when on LAN

```bash
export KUBECONFIG="${KUBECONFIG_LOCAL}"
```

## Verification & Testing

### Test kubectl via Tailscale

```bash
# From a machine on the tailnet (not on the local LAN)
export KUBECONFIG="${KUBECONFIG_TAILSCALE}"

# Should return cluster nodes
kubectl get nodes -o wide

# Test a more complex operation
kubectl -n kube-system get pods
```

### Test talosctl via Tailscale (Approach B only)

```bash
# From a machine on the tailnet
export TALOSCONFIG=./talos/talosconfig

# Resolve Tailscale MagicDNS
tailscale status | grep cereal

# Access Talos API
talosctl version --nodes cereal.tailnet.ts.net
talosctl service etcd --nodes cereal.tailnet.ts.net
talosctl logs kubelet --nodes snap.tailnet.ts.net
```

### Verify node-to-node Tailscale connectivity

```bash
# On a Talos node (via talosctl shell or debug pod)
# Nodes should ping each other over Tailscale IPs
talosctl debug --nodes cereal.tailnet.ts.net
# Inside the debug shell:
ping -c 3 $(tailscale ip -4 snap)
```

## Troubleshooting

### kubectl hangs or times out

1. Verify your workstation is on the tailnet:
   ```bash
   tailscale status
   ```
2. Verify the operator pod is running:
   ```bash
   kubectl --kubeconfig="${KUBECONFIG_LOCAL}" get pods -n tailscale
   ```
3. Verify the operator machine is in the tailnet:
   ```bash
   tailscale status | grep tailscale-operator
   ```
4. Check Tailscale ACLs allow your device to reach `tag:k8s-operator` on port 443.

### `tailscale configure kubeconfig` fails

```bash
# Check the operator hostname is resolvable
nslookup tailscale-operator.your-tailnet-name.ts.net

# If using a ProxyGroup, get the correct URL:
kubectl --kubeconfig="${KUBECONFIG_LOCAL}" get proxygroup -n tailscale
# Then use the printed URL:
tailscale configure kubeconfig https://proxy-group-name.your-tailnet-name.ts.net
```

### Talos node not appearing in tailnet (Approach B)

1. Verify the auth key is valid and not expired (max 90 days for auth keys).
2. Check Talos extension logs:
   ```bash
   talosctl logs -f extension-tailscale --nodes cereal
   ```
3. Verify the node has internet access to `login.tailscale.com`.
4. Check the machine is tagged correctly in the Tailscale admin console.

### RBAC denied errors via Tailscale

The API server proxy impersonates your Tailscale identity. If you see RBAC errors:

```bash
# Check what user/group Kubernetes sees:
kubectl --kubeconfig="${KUBECONFIG_TAILSCALE}" auth whoami

# Verify the RBAC binding matches that user/group:
kubectl --kubeconfig="${KUBECONFIG_LOCAL}" get clusterrolebindings
```

For tagged devices, Kubernetes sees the group as `tag:<tagname>` (e.g., `tag:k8s-readers`).
For untagged users, Kubernetes sees the user as the tailnet email (e.g., `user@example.com`).

### Certificate errors

The Tailscale API server proxy uses Tailscale-generated TLS certificates (via Let's Encrypt for tailnet domains). If you see certificate errors:

1. Ensure [HTTPS is enabled](https://tailscale.com/docs/how-to/set-up-https-certificates) for your tailnet.
2. Wait a few minutes after operator deployment for certificate provisioning.
3. First connection may be slow — the certificate is provisioned on-demand.
